# 续传和自动跳过（v0.2.10）

上传和下载不需要额外设置，也不会弹出覆盖或跳过确认。

- 取消或失败后，可以在 Activity 中重试，也可以重新选择原文件或远程路径。源内容不变时会复用已保留的部分数据；关闭应用后也能继续。
- 每次检查实际文件，比较两端 SHA-256。内容相同直接跳过，Activity 显示 `Skipped`，仍然复制可用的目标路径。历史记录不是跳过的依据。
- 目标被删除时重新传输。重名但内容不同的文件保留原件，新文件使用 `-2` 等后缀。已存在的后缀副本也参与内容比较。
- 上传会检查 `.agent-inbox` 的日期子目录，因此跨天重复上传相同文件也可以跳过。查找范围为同名文件及 Agent Drop 支持的 100 个重名候选。
- 目录按相对路径、文件 SHA-256、空目录和符号链接目标生成清单。大目录也使用 rsync，支持目录内已完成文件及未完成文件的续传。
- 传输前后源内容发生变化、读取失败或 SHA 校验失败会报错，不会将未校验数据标为成功。

上传的未完成数据保留在远端 `~/.agent-inbox/.partial/`，下载的未完成数据保留在目标目录的 `.agent-drop-partial/`。这些是续传数据，不是最终完成文件。手动删除这些目录会失去相应的续传进度。源内容变化会使用新的续传区，以免把旧内容误认为新文件。

远端需要 `rsync`、POSIX shell、`base64`，以及 `sha256sum` 或 `shasum`。缺少 SHA 工具时会明确失败，不会仅凭文件大小或时间跳过。

本次验收对应 issue #27：RESUME-1（双向续传）、SKIP-1（实际内容校验和跳过）、RELEASE-1（PR、合并、发布和本机安装）。功能验证使用隔离本地 SSH 适配器、真实系统 rsync 和 SHA 工具，不接触用户服务器；测试包含实际取消、部分数据保留和重试时的 matched-data 统计。
